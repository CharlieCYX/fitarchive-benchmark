# Reference: FitArchive Master Roadmap 2026–2027 — Summary

Faithful distillation of `FitArchive_Master_Roadmap_2026_2027.pdf` (prepared for
Charlie, 24 Sep 2026). The PDF itself is intentionally not committed (see
DECISIONS.md ADR-007). This summary exists so agents can work without re-reading it.

## Core idea & the one rule
- **Core idea:** Find overlooked secondhand fashion → curate real drops → market
  better → launch → learn from real customer behavior → make the next drop smarter.
- **ONE RULE:** Never learn/build a tool just to list it. Every new skill or
  capability must produce a visible output: output, decision, prototype, dashboard,
  garment, or result.
- **Caveman summary:** Find clothes → make them desirable → sell → see what worked →
  use the numbers → smarter next drop → learn fashion tools → improve a garment →
  solve one digital fashion problem → build one real feature.

## Three portfolio pillars
- **A — Circular commerce + merchandising:** sourcing, curation, pricing, customer
  definition, campaign, sales.
- **B — Fashion intelligence + analytics:** marketplace observations, own launch
  data, Power BI dashboards, SQL/Python later when justified.
- **C — Fashion innovation + technology:** Illustrator/CLO garment improvement + one
  Figma/product/software case study tied to a real fashion problem.

**What it is NOT:** not instant fashion-designer cosplay; not a fake startup with
screens but no users; not 20 disconnected TikTok projects; not "learning CLO/Figma/
Python = qualified for specialist jobs."

## Build sequence (21 phases)
**Phases 1–9: market → drop → analytics**
1. Learn fashion-business basics (merch vocabulary; 1-page glossary; review 3–5
   brand drops). NO Python/Power BI/CLO/Figma/SQL yet. → foundation note.
2. Marketplace research: structured dataset (brand, category, aesthetic, colour,
   price, condition, engagement, listing age, seller/source, notes); manual first
   sample; tag Drop #001 candidates. → **Market Dataset V1**.
3. Curate Drop #001: ~15–30 coherent pieces; seller permission documented;
   collection name/story/price range/heroes; inventory+pricing sheet. → assortment
   board + sourcing rationale.
4. Customer + collection strategy: primary + secondary persona; price ladder;
   entry/core/hero tiers. → persona + strategy sheet.
5. Campaign + digital presentation: moodboard, truthful imagery, editorial assets,
   product copy, landing page, launch calendar. AI creative only where useful and
   disclosed. → campaign deck + launch assets.
6. **Launch Drop #001:** real people react; track views, clicks, saves, enquiries,
   purchases, sell-through, revenue, item-level interest. → real launch data.
7. Analyse: clean results in Excel; compare item/price/category/creative/traffic;
   learn Power BI; write 5–10 decisions for Drop #002. → Performance Report +
   dashboard.
8. FitArchive Intelligence System: combine market + own data; reusable dashboard
   views; document what decision each view supports; repeatable pre-drop research
   process. → intelligence dashboard that changes decisions.
9. Drop #002 from data: one-page hypothesis based on evidence; curate, launch,
   compare vs Drop #001; document what improved. → before/after proof the loop works.

**Phases 10–15: Illustrator/CLO → garment innovation**
10. Illustrator for fashion: 3–5 technical flats + colourways using a real
    FitArchive garment. → technical-flat sheet.
11. Garment construction/pattern basics → CLO 3D beginner exercises; recreate/modify
    garments; renders + fit views. → 2–3 digital garment exercises.
12. Garment Innovation Lab: pick ONE real garment problem (fit, comfort, movement,
    pockets, proportions, waste, modularity, upcycling); user/review evidence or
    wear testing; measurable problem definition; before-state record. → framed,
    evidenced problem (not an AI-generated idea).
13. AI structured ideation AFTER the problem is defined; record selection criteria;
    choose 1–2 concepts; document AI vs manual contribution. → ideation board.
14. Develop/test redesign in Illustrator + CLO (Stress/Strain/Fit/Pressure maps);
    before/after flats; document simulation limits. → before/after case study.
15. One physical prototype (own item or explicit permission); small user wear test;
    photos + feedback; compare with CLO predictions. → physical case study.

**Phases 16–21: digital fashion product → marketplace**
16. Notice a repeated digital fashion problem from real operations/users; interview
    users; current workaround; one target outcome. → validated problem brief.
17. Design ONE coherent digital product (closet/outfit/style-reco/sustainable-finder
    as features of one system, not separate apps); core journey; V1 vs future. →
    product concept.
18. PM work before code: competitor research, feature matrix, user stories, PRD, MVP
    definition, roadmap, success metrics. NO backend yet. → mini product case.
19. Figma clickable prototype; test with users; revise once. → prototype + test
    summary.
20. Build ONE real feature (outfit suggestion, fit guidance, wardrobe matching,
    secondhand finder…); simple stack; test with real users. → working feature with
    evidence.
21. FitArchive itself becomes the circular marketplace — the container for
    everything; keep intentionally small until demand exists. → coherent product
    ecosystem.

## First 30 days checklist
- W1: learn merch terms; design dataset columns + tagging rules; pick 2–3
  categories/aesthetics; folder structure for evidence.
- W2: collect first manual sample; mark Drop #001 candidates; 3 pivot views
  (brand/category, price band, aesthetic); 5 observations without overclaiming.
- W3: choose drop concept; shortlist + contact sellers; inventory/pricing sheet;
  persona + moodboard.
- W4: finalize permitted assortment; creative direction; campaign assets/landing
  draft; define launch metrics.
- **Do NOT start in month 1:** Python, SQL, CLO, Figma, AR, recommendation engines,
  automated scraping, custom marketplace backend.

## Operating guardrails & proof standards (§12)
- **Marketplace/seller integrity:** permission before representing items; never
  imply ownership you don't have; no altering others' garments without explicit
  permission; respect platform terms (manual collection > scraping for V1).
- **AI transparency:** disclose synthetic imagery; AI = ideation accelerator, never
  proof a garment works; validate with drawings/CLO/physical tests.
- **Analytics honesty:** tiny dataset ≠ "prediction model"; distinguish
  observation/hypothesis/validated result; no retention models without repeat-customer
  data; simple analysis first.
- **Portfolio proof standard:** every headline claim has an openable artifact; every
  case study = problem → evidence → decision → execution → result → reflection;
  state exact contribution on collaborative work; label unfinished ideas as
  concepts/prototypes.
- **THE CV TEST:** if an interviewer says "show me", you must be able to open
  something.

Closing line: *Start small. Ship Drop #001. Learn from real behavior. Add complexity
only when the next problem requires it.*
